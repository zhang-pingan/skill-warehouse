# 历史与记忆

## 历史导入与会话任务

DSH 导入用户请求、助手可见回复及工具结果，排除注入指令、思考内容和本插件后台分析会话。Codex 导入可识别 rollout 消息与执行记录，保留仅出现在结束事件中的最终回复，去掉重复的结束回显。导入不按默认查询天数删除或排除旧会话；原始文件只读。Codex 写入失败时保留当前分块游标，恢复后重复读取该块，稳定消息身份避免重复入库；失败记录不会被游标跳过。

新消息先进入暂存清单。AI 按完整快照分批判断目标及消息归属，支持 A—B—继续 A 和共享消息；任务按目标划分，不把消息数量或时间间隔当作任务边界。任务限定在所属会话内，跨会话的相关工作通过共享实体、记忆和来源查找，不按相似标题合并；不提供人工跨会话合并或拆分工作流。

例如，同一会话的消息 1–9 处理题目提示 A，10–20 修复输入 B，21–25 继续 A，26 同时报告 A、B。任务 A 可关联 1–9、21–26，任务 B 可关联 10–20、26；共享消息 26 只保存一份来源和证据。检索按这两个工作目标组织结果，具体工具输出在任务原文中按需读取。

每个分块必须完整覆盖输入消息；缺失、重复或未知消息 ID 会作为诊断反馈给模型，在 `memoryExtractionRetryLimit` 内重试当前分块。无效 JSON、空文本和输出超限也属于可反馈的输出错误；失败输出不改变已有任务目录或归属，来源版本变化及数据库发布失败不会作为模型输出错误重试。最终整合只允许将新任务草稿合并到另一新草稿或已有任务，已发布任务 ID 始终保留；非法合并反馈允许的来源和目标 ID，修正后才发布。Host 在最终验证通过后一次发布任务、正式来源证据和归属。

来源已读、归属已发布和记忆已提炼是不同进度。归属状态区分尚未分析（`unprocessed`）、待归属（`unresolved`）、无任务（`no-task`）和已归属（`assigned`）。待归属消息在有新上下文时与新增消息一起重新判断，未变化的会话不会反复分析；无任务消息保留来源，不单独安排自动偏好提炼。尚未分析内容计入积压，可通过补充原文检索读取，不当作已完成目录。

每个任务具有稳定 ID、所属会话、标题、目标、过程概述、历史状态、实际活动时间和内容版本；版本绑定标题、目标、概述、状态与来源哈希。重新扫描不会把历史工作改成今天发生。来源变动在独立版本中保留，旧引用仍可追查；正在分析的快照变化会拒绝发布并重试。

## 记忆提炼与有效性

任务版本变化后安排提炼，输入包括任务目标、概述和带原始定位的完整消息或连续摘录。已发布任务的待提炼版本先于新的会话归属分析处理。模型可以不生成任何长期记忆；空结果通过校验后将该版本标记完成。Host 在每个分块内检查精确引文、别名原文、规范名唯一性、实体引用及记录字段；字段或引用校验失败、JSON 未闭合、空文本及输出超限时只重试当前分块，将字段位置和错误值作为诊断数据反馈给模型，每块最多调用 `memoryExtractionRetryLimit` 次，已验证分块在本次运行中复用。全部输入成功后原子保存候选和任务关联。模型调用或发布失败停止该任务，保留失败执行记录；来源读取或分块准备失败也计入任务尝试次数，并显示在当前队列错误中。旧版本不能确认新版本已处理，也不改写新版本的错误或消耗其重试次数；过时结果的失败记录仍留在执行日志中。其他任务遗留的失败不会阻止本轮继续处理成功批次，当前批次新失败才停止本轮；本轮处理数量累计所有完成的批次。

实体和记忆按既有身份规则复用。新生成的内容由 Host 强制保存为候选，模型额外返回的确认状态不能提升可信度；重复来源、任务关联或存放时间也不会自动确认。已确认、已撤回、已取代和超出有效期的内容继续沿用既有检索规则。默认 90 天的候选复核提醒不改变可信状态；`valid_from`/`valid_to` 决定事实适用时间。

任务标题、概述和记忆等生成内容使用[后台默认语言](settings-and-operations.md#设置页)。

## 检索与来源读取

检索使用本地文字索引和文本匹配，不使用向量数据库。`search_history` 联合检索任务标题、目标、概述和原文，并按任务 ID 去重分页。多个工具输出不会成为多项工作。`sort=recent` 按来源活动排序；默认相关性优先。时间范围内必须确有任务消息，不能只看首尾时间跨度。任务发现允许由较早原文召回近期继续的目标；页面开启原文搜索时，则限定原文自身的时间范围。

`memory_search` 分开返回 `sessionTasks`、记忆、实体、关系和助理任务。持久任务账本为空不能推导历史工作不存在。未归属原文也参与补充召回，应用来源系统、会话、项目、实体、状态和时间筛选；指定某个任务时不混入未归属结果。`search_history` 分别返回任务与补充原文的总数和继续分页标志。`memory_search.historyPage` 返回这两组结果的总数、`hasMore` 和 `nextOffset`；继续查询时把 `nextOffset` 作为 `offset`，记忆等知识分组仍是各自受限的首批结果。结果带查询范围、处理覆盖和错误；只能说“在当前已处理范围未找到”，不能把积压误报成没有历史。

历史原文查询先筛选任务，再批量读取消息关联与活动时间，逐条扫描文字索引；同一索引正文只匹配一次，共享消息分别计入所属任务。每个任务保留完整命中数与最多五条片段，片段按消息 ID 的 SQLite BINARY 顺序、再按索引行号排列，不影响任务本身的相关性与活动时间排序。未归属原文逐条读取、匹配和计数，只保留当前页，避免为分页保留全部正文；归档损坏仍报告错误。请求之间不缓存结果，修改和删除在下一次查询可见。匹配继续使用既有 Unicode 规范化、中文子串和英文词边界规则。

历史检索、记忆搜索、记忆列表与详情及执行目标发现由插件拥有的单个 Node.js 查询线程处理，无需修改 Harness。线程首次查询时启动并复用，以独立只读 SQLite 连接读取同一数据库；每次请求使用一个事务快照，避免多条 SQL 混合不同提交版本，后续请求读取最新已提交数据。扫描、正文解压和结果组装在查询线程完成，Host 异步等待结果；写入和后台任务仍由 Host 管理。

请求有数量上限与总超时，等待排队也计入超时。取消排队请求只移除该请求；取消执行中请求先终止并等待线程回收，再处理其他请求。线程异常或超时明确报错，不退回 Host 同步扫描，也不返回伪空结果。插件卸载和记忆初始化等待查询线程停止后才释放或清空数据库。运行限制见[设置与运维](settings-and-operations.md)，测量范围见[B0 性能基线](../test/evaluation/README.md#b0-性能基线)。线程隔离不消除扫描成本；结果跨线程传递、Host 序列化及其他同步操作仍可能造成短暂延迟。

使用 `memory_get(sessionTaskId)` 读取概况、关联知识及分页消息；随后按 `evidenceId` 读取完整来源与附近会话消息。消息携带多个所属任务时保留这些关联。`historyMessageId` 用于无任务或待归属来源。任务消息分页传回 `version`，版本变化时要求刷新。

## 记忆管理

左侧查询对象，中央星云显示关联，右侧先展示内容并按需展开来源和管理。默认搜索会话任务、记忆和实体自身文本；“搜索原始对话与执行记录”默认不勾选，只作用于当前页面的搜索请求，不限制助理工具检索或已知来源读取。无命中时用户可以显式开启。开启后原文命中归组到所属任务，独立按钮直接定位来源；尚未分析、待归属及无任务命中列为补充结果。“加载更多”分别追加两组结果，补充原文不会因任务结果为空而停在第一页。重置恢复为关闭，关闭高级筛选后有效开关仍可见。

查询、重置、取消选中及记录管理按钮使用当前皮肤的控件样式；列表与详情内的关联条目统一呈现，长文本自动换行，悬停和键盘焦点可见。管理、来源及维护区域使用可旋转的折叠箭头。

星云节点包括会话任务、记忆、实体和助理任务，关系只画连接线，消息与证据不生成节点。已加载的节点及可展示关系默认全部绘制，后续分页补齐与前页节点之间的关系。节点按类型形成带名称的彩色云雾区域，采用星点核心、景深柔光、轻微漂浮和呼吸闪烁；悬停与选中使用粉紫纹理光晕、呼吸双圈及十字引导线。关系采用弧线、柔光带与沿线流动的光点，全部关系保持可见，选择不会压暗其他节点或背景。鼠标附近的局部距离和节点大小随距离平滑放大，命中节点显示光圈和名称；悬停只临时突出关系，点击才打开详情。移开后保留点击选择；拖动不会误触点击。点击关系线打开关系类型、两端对象和已有来源，任务自动关联只提供说明与端点跳转。点击空白处、再次点击选中的节点或关系线、详情标题旁的“取消选中”按钮及 Esc 均可立即清空选择，未完成的详情请求同步取消，光圈与关联线高亮随后平滑淡出；无选择时 Esc 关闭记忆页面。触屏直接点选，键盘通过列表打开相同对象。

空闲时星云缓慢自转；鼠标进入图中或已有选择时暂停自动自转与漂浮，方便命中。滚轮围绕指针平滑缩放，拖动旋转在松手后保留惯性并逐渐停止，选中节点或关系线时同样生效；Shift 拖动平滑移动，双击复位。空心节点表示补充关联。背景由蓝紫云雾、五层星尘轨道、中心旋臂光晕和视频组成，不随记录数量或选中状态隐藏，装饰粒子不可选中。系统开启减少动态效果时，星云保持静态；页面隐藏时暂停画布动画，关闭后释放动画、监听和纹理。页面区分数据库总量、已加载检索结果和星云节点数，不把当前图谱称为全量。窄屏查询和详情使用抽屉。查询和来源分页拒绝旧请求覆盖新结果。

记忆提炼入口集中提供立即提炼与重试失败作业。失败执行列表默认折叠，按开始时间和稳定 ID 分页；成功、无产出成功不在列表中，原生执行日志仍保留。历史失败次数和当前失败作业数分别显示。折叠停止自动加载，分页失败保留已加载条目。

## 归档与删除

默认查询窗口 30 天、热正文 90 天、候选复核 90 天、容量 10 GiB，可在设置修改。查询窗口不限制导入，不删除历史。归档仅保存在本地数据库，不提供跨设备归档。较早任务在提炼完成后按来源 gzip 压缩，整个已导入过程可读取，不只留下被记忆引用的片段；共享近期消息受保护。索引保留检索能力，冷数据不降低相关性或可信度。

删除会话任务只删除其独占消息和可移除派生记录，共享消息保留；最小导入排除标记阻止下一次同步恢复已删除的本地记录。删除同步更新会话修订号、清除旧修订的重试次数与错误，并更新剩余任务的来源版本，在途归属和提炼不能复活已删除记录或确认过时版本。托管备份同步清理。容量不足会停止新增输入并报告调整容量或明确删除的操作，不自动抛弃旧内容。初始化范围见[设置与运维](settings-and-operations.md#初始化记忆)。

当前执行请求可以将历史 `sessionTaskId` 与管理 Task 关联，保存原生来源、消息引用和内容版本；导入本身不创建可执行 Task。联合发现以工作目标区分同一会话内的多个历史任务，来源版本变化不会重写已保存的执行决定。执行续接与恢复规则见[任务与执行](tasks-and-workers.md)。
