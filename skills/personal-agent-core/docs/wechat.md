# 微信与主会话互通

微信通道通过腾讯 iLink 与桌面私人助理共用一个原生 DSH Session、上下文、模型和访问设置。实现和界面均在 `personal-agent-core` 内，使用 Harness 的主题与凭证服务；不依赖皮肤插件、社区微信插件、公网回调服务器或远程二维码生成服务。

## 接入

1. 在已加载当前插件的 Harness 中打开设置 → 私人助理 → 微信接入；Host 源码更新后需先重启应用。
2. 开启微信接入，等待“修改已生效”后点击“扫码连接私人助理”，用本人微信完成扫码授权。
3. 从扫码使用的微信给机器人发一条纯文字消息。Host 将发送者 `from_user_id` 与登录返回的扫码人 `ilink_user_id` 精确比对，一致时自动绑定并处理这条消息，界面显示“已绑定 · 与扫码账号一致”，无需额外点击确认。缺少扫码人 ID 时提示重新扫码；不一致的发送者不能进入主会话。
4. 点击“打开主会话”进入私人助理页面；微信自动共用该页面的唯一主会话，无需选择或另行绑定。
5. 在微信发消息，在桌面继续同一对话；主会话最终答复默认同步到已绑定微信。

身份标识用于精确比对，不是用户可识别的微信号。当前插件不获取微信昵称、微信号或头像，也没有通过 `from_user_id` 查询个人资料的入口；用户依据“与扫码账号一致”判断身份，无需辨认内部 ID。手机聊天中的头像由微信客户端和上游账号资料决定，插件没有头像配置或上传能力。

首次自动核验绑定时从主会话当前位置开始同步，不补发旧历史；若当前轮次正在进行，会继续观察其完成结果。Host 合并并发创建请求，桌面和微信使用唯一绑定；尚无绑定时创建专用主会话，不从历史会话标记中选取。空白主会话被原生页面切到其他默认模式时，接入前恢复标准模式。目标缺失、归档或已开始轮次后的模式不符时暂停派发并显示错误，恢复该会话数据、解除归档或恢复标准模式后重试，不自动新建替代会话。

主会话空闲时，助理上下文保存在原生待处理队列中，下一条消息唤醒后再进入模型；这不阻止微信连接或结果观察，也不需要先打开桌面主会话。重复待处理上下文通过一次原生队列更新合并为一份，保留其他待处理消息和原始 Session 日志。正在运行的轮次可能已领取上下文，尚未提交期间不会重复注入。

通道仅支持一个机器人账号与一个经扫码核验的本人私聊身份。未验证消息最多保留 16 个发送者标识，不保存其回复凭证或提交正文。已有本地确认的授权保持有效，显示“此前已在本地确认”；重新扫码并发送消息后可获得扫码一致性标记。群消息不进入通道；媒体与文字混合消息整条不提交，并回复纯文字限制提示。图片、语音、文件、视频和多账号不受支持。腾讯登录资格、接口可用性和账号额度取决于服务端。

设置中的[清空主会话历史](settings-and-operations.md#主会话维护)会保留扫码授权、本人身份和 iLink 接收游标，暂停并排空当前通道工作后，在同一账本事务中切换唯一 Session、绑定版本及事件观察位置。旧会话待处理输入隔离、待发输出取消，未知发送保留核对记录；恢复后新消息进入新主会话。微信命令不能触发清空。

## 连接状态排查

| 界面状态 | 处理方式 |
| --- | --- |
| 未启用 | 开启微信接入，等待设置生效 |
| 请从扫码使用的微信发送消息 | 用刚才扫码的账号给对应机器人发送纯文字，等待自动核验 |
| 需重新扫码以验证账号身份 | 登录凭证缺少扫码人 ID，重新扫码并发送消息 |
| 收到的消息与扫码账号不一致 | 使用扫码账号发送消息，不确认其他发送者 ID |
| 已绑定 · 此前已在本地确认 | 本地授权有效；需要扫码一致性标记时重新扫码并发送消息 |
| 登录失效 | 重新扫码登录 |
| 账号被占用 | 停止使用同一机器人账号的其他 Host 或微信插件，再刷新 |
| 备份恢复暂停 | 在本地检查旧输入和发送状态后确认恢复；历史输入不会自动重放 |

接入失败优先查看微信模块保留的错误和收发队列。单纯处于空闲、助理说明仍在待处理队列中，不需要先在桌面打开主会话；缺失、归档、模式冲突或持久化错误按具体原因处理。

## 同步与控制

| 设置 | 默认行为 |
| --- | --- |
| 启用微信接入 | 关闭 |
| 同步主会话最终答复 | 开启，覆盖微信和桌面发起的轮次 |
| 镜像桌面用户原文 | 关闭；不影响共享上下文 |
| 微信远程审批 | 关闭；本地明确开启后仅允许一次性决定 |

微信正文通过原生 `sessionController.prompt()` 以 queue 模式进入主会话，不自动 steering。账号、联系人和外部消息 ID 映射到稳定 requestId，重复拉取或持久化确认失败后的恢复沿用同一身份。数字消息 ID 按响应中的原始十进制文本保存，支持超过 JavaScript 安全整数范围的 64 位编号，避免精度丢失导致拒收或错误去重。微信原文只在主会话保存一份，并进入既有历史与提炼流程。

空闲通道直接读取持久会话记录与投递游标，不恢复 Agent 或注入上下文；收到待处理微信输入或打开私人助理页面时才恢复主会话。输出观察使用 Session projection 和持久游标，只发送已提交且正常结束轮次的最终正文，不转发推理、工具日志或中间输出。微信发起的轮次取消、错误结束或没有正文时返回状态说明。长答复按 Unicode 字符稳定分段并顺序发送，领取剩余部分不会重新运行模型。

| 指令 | 效果 |
| --- | --- |
| `/wx-status` | 查看通道、主会话和待发数量 |
| `/wx-session` | 查看当前固定主会话及状态 |
| `/wx-pending` | 刷新互动后领取等待续发的内容 |
| `/wx-stop` | 只请求停止能够确认全部输入均来自微信的当前轮次；混合桌面输入时留给桌面处理 |
| `/wx-answer 编号 1:A 2:A,B` | 按问题编号回答；单选不能给多个选项，多选使用逗号 |
| `/wx-answer 编号 -- 回答内容` | 回答单个自由文本问题，或以自由文本替代单题选项 |
| `/wx-approval 编号 allow` / `deny` | 同意一次或拒绝当前审批，不允许永久授权 |

控制指令不再次触发模型。停止指令先保存处理记录与回复，再尝试取消当前轮次；记录无法保存时不执行取消，结果不明确时也不自动再次取消后续轮次。微信不能切换任意 Session、修改模型、提升访问模式、修改 feature flags、初始化记忆或调用通用 operator 接口。

## 提问与审批

普通选项问题和单题自由文本支持微信与桌面共同答复，只有一个最终决定生效。原生提问和审批先保存最终状态，再把决定返回给调用方；保存失败会撤回桌面请求并报错，不授予权限。桌面已处理或连接已变化的卡片会在发送前再次核对，不会因本地重试而重新激活。微信先答会取消桌面的同一请求；桌面先答会失效微信编号并撤回尚未发送的卡片。没有桌面答题器时微信继续等待，到有效期、原请求取消或通道关闭时结束。失效编号、重复题号、未知选项、遗漏问题、多余字段和错误命令类型均不能提交。

包含权限或计划审阅 intent 的原生问题、超过 26 个选项的问题、多题且含开放问题的请求保留桌面处理。微信不把这些请求降格为普通问答。

远程审批默认关闭。开启后，DSH 原生权限请求只返回 `allowed-once` 或拒绝，不设置权限策略。有关联工具调用时，卡片包含原始调用参数；无法找到该调用或整张卡片超过单段预算时留在桌面处理。Codex 仅支持命令、文件更改和当前 turn 的权限请求，校验所属任务、主会话、待处理审批、adapter 实例与连接 epoch；其他 Codex server request 必须在桌面处理。微信审批卡保留完整请求参数，范围与应答命令必须能放进同一段消息；过长、缺少完整文件更改内容或无法确定可用决定的请求保留桌面处理。Codex 未显式提供决定列表时，使用协议规定的一次性 accept / decline；显式列表仍须逐项校验。连接变化后的卡片失效，不能跨连接批准。微信没有通用 operator token。

## 队列与恢复

微信开关修改后自动应用，页面显示应用进度与结果；连接状态以 Host 的有效配置为准。扫码入口说明授权范围，收到来自扫码账号的消息后自动核验绑定。账号内部 ID 收在“账号标识”详情中。若显示消息身份或格式错误，接收停止且保留游标；修复原因后点击微信区域的“刷新”，Host 代码更新则先重启 App，重新接收保留的批次。无需为此解绑、重新扫码或清空记录。

关闭 App 后不收发；重启后在开关开启、凭证有效且无恢复 hold 时自动继续。接收网络故障按退避重连。收件与待发分别受 `wechatQueueCapacity` 限制。拉取批次可按空位保存部分消息，只有全部接收完成才推进拉取游标；重拉会跳过已保存的身份。待发拥堵不占用收件容量，因此仍可接收领取和审批指令。长答复按空位保存分段，全部分段入队后才推进会话事件游标；已发送的分段不会重复生成。尚未完成的输出保存原始分段长度，修改 `wechatMessageChars`、清理已发送正文或重启均不改变剩余分段的边界。新增内容等待空位期间，已有待发继续发送。正常空轮询不会清除仍待处理的派发或投递错误。

| 投递状态 | 处理方式 |
| --- | --- |
| 待发 | 按同一绑定顺序发送 |
| 服务端已接受 | HTTP 成功且 JSON 响应没有非零错误码，允许省略默认零状态字段；不自动重发，不代表手机已经收到 |
| 连接尚未建立 | 仅 DNS、连接拒绝或连接建立超时等可确认未提交的错误有限退避重试 |
| 等待互动 | 回复凭证过期或发送预算用尽；从本人微信发 `/wx-pending` 后继续 |
| 失败 | 停止后续顺序投递，在本地核对原因并重试或跳过 |
| 结果未知 | 请求可能已提交；不自动重发，先核对手机，本地确认后才可重发 |

确认未提交的连接失败，以及发送前撤回的卡片，会归还同一次互动的额度；已刷新为另一份回复凭证时不改动新额度。额度恢复写入失败会暂停该消息，交由本地检查。

Socket 中断、请求超时、无效响应或未明确确认的 HTTP 结果都可能意味着已经提交，不能当作安全的自动重试。Host 在发送期间停止时将该段保存为结果未知。每个分段的身份、内容与已接受状态持久化；保留期限只抹去已结束正文，保留去重身份。

设置中的收发队列展示失败、未知和隔离记录。重新登录会隔离旧输入，取消尚未发送的旧输出；旧内容不会改投新目标。旧绑定的未知结果保留供核对，不能直接重发。解绑停止通道、撤销凭证并清空当前身份，保留队列记录供核对。

初始化记忆先暂停并排空微信操作，保留主会话绑定、微信授权与收发记录，完成后恢复。数据库备份包含非秘密通道记录，缺少 Harness credentials 和原生 Session；恢复后的通道保持暂停，必须本地确认。从备份恢复继续时隔离旧输入和待发内容，从当前主会话位置重新观察，避免自动重放可能已执行或已送达的历史。

## 配置与凭证

| Config / runtime setting | 默认值 | 范围 |
| --- | --- | --- |
| `wechatRequestTimeoutMs` | 15000 | 1000–120000 ms |
| `wechatPollTimeoutMs` | 38000 | 1000–120000 ms |
| `wechatBackoffMaxMs` | 60000 | 1000–3600000 ms |
| `wechatMessageChars` | 1800 | 100–4000 字符 |
| `wechatQueueCapacity` | 2000 | 收件、待发各 10–100000 条 |
| `wechatRetentionDays` | 90 | 1–3650 天 |
| `wechatInteractionTtlMs` | 600000 | 1000–3600000 ms |
| `wechatContextTtlMs` | 600000 | 1000–86400000 ms |
| `wechatSendBudget` | 8 | 每次有效互动 1–10 段 |
| `wechatSendRetryLimit` | 3 | 确认未提交时额外重试 0–10 次 |

默认锁目录为 `~/.dsh/locks/personal-agent-wechat`，由 Config `wechatLockDir` 指定绝对路径。同账号通过文件锁只允许一个 Host 收发和执行账号管理；共用账号的实例应共用锁目录。恢复发送状态、自动身份核验、解绑和队列修改均须先取得锁，自动身份核验期间持锁直到写入完成。抢锁失败的实例不能改变活动实例的记录或撤回其审批。登录完成、失败或取消后，未运行通道的实例释放其登录资源与账号锁。实例卸载先取消收发和互动，再等待管理操作、在途写入及桌面互动撤回完成，最后释放锁和数据库；仅由桌面处理的请求不归微信通道等待。

生产服务固定使用 `https://ilinkai.weixin.qq.com`，登录返回地址仅接受对应腾讯 HTTPS 域，不跟随携带 token 的重定向。扫码人 ID、机器人 token 和回复 context token 由 Harness credentials 保存，键按数据库路径隔离；token 不返回客户端状态、日志或模型输入。扫码人 ID 用于 Host 身份比对，已绑定发送者 ID 可在设置的“账号标识”中查看。设置管理接口要求有效的本地连接认证，不接受通用 operator token 代理微信授权。二维码在 Host 本地生成。

## 验证范围

微信协议测试和真实 Harness 夹具的运行方法、覆盖范围及页面核对项统一维护在[验证](verification.md#微信互通)。这些检查不验证腾讯账号资格或手机实际送达；服务端已接受也不能代替手机端核对。
