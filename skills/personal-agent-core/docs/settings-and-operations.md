# 设置与运维

## 设置页

Harness 左下角设置中的私人助理页面按主会话、历史同步、收件箱恢复、数据库备份、记忆提炼、归档与保留、后台分析、微信接入和 Worker 分组。每个模块都有用途说明，可独立展开与折叠；不直观的设置在字段旁解释。页面使用 DSH 主题 token 和 Client 控件，随当前皮肤配色。

设置修改后自动应用，无需点击保存。开关和选择项立即提交，数字和文本输入在停止输入约 450 毫秒或离开输入框时提交。页面显示待应用、正在应用、已生效、校验失败或请求失败。无效输入保留在原字段并显示原因；它不会阻止无关的有效修改。网络或 Host 错误保留编辑内容，可点击“重试”；只有服务端确认后才显示已生效。关闭设置页会提交待处理的有效修改，切换页面不会取消在途请求；直接退出 App 前应等到“修改已生效”。

首次运行时，Cordis 配置提供默认值；已保存设置覆盖默认值。应用前会校验数值范围、租约与心跳关系、preset 选择、默认 worker 和模型策略引用；有引用关系的设置一起校验和提交。恢复默认值需要确认，随后立即应用当前 profile 的有效初始值，Codex 开关保持现状。

Codex 历史和 worker 开关位于 Worker 设置，默认关闭。启用会同步历史，并统一开放 App Server 连接、新建、续接和按用户明确要求分叉任务；设置与这些操作开关在同一事务中保存。启动时按已保存的 Codex 开关同步操作权限，已开启的配置无需重新切换。`control.steer` 保持独立授权，原生队列写操作不可用。关闭会等待扫描和连接操作完成，断开插件自己的连接，并清理可移除的本地历史镜像与游标；有正在派发的请求或未结束、待对账的 Codex 执行时拒绝关闭并说明原因。开关操作期间禁用其他配置修改。

各模块的批次、读取预算、重试次数和高级参数收在“高级设置”中。后台分析用于控制模型生成内容的语言、任务关联与资源限制；记忆提炼的单次请求时限位于记忆提炼模块。历史正文保留、候选复核和容量设置位于归档与保留。后台运行状态独立折叠，展开后查看运行状态、上次成功、下次运行及最近错误，可用标题旁的刷新按钮更新。

Worker 模块提供“默认 worker 优先级”，默认 `dsh_standard`（DSH 标准模式），另有 `dsh_cordis`（DSH 创造模式）；启用 Codex 后增加 `codex`。模型判断为新建或维护 DSH 插件时可显式选创造模式，其他新 worker 使用该默认值；已有任务沿用原会话。关闭 Codex 且当前默认值为 `codex` 时，插件优先回退到允许列表中的 DSH 标准模式，其次选择 DSH 创造模式；两者都未允许时拒绝关闭并提示先调整允许列表，原设置与权限保持不变。已有 DSH 默认值不会改变，插件也不会扩大允许列表。重新启用 Codex 不自动改变默认值。

Worker 模块的“工作目录白名单”对应 `allowedWorkspaceRoots`，DSH 与 Codex 共用。默认空列表，不增加插件层的目录限制；填写后，每行一个绝对目录，允许该目录本身及其子目录。设置即时保存，下一次派发按最新配置检查，不中断已经运行的任务。路径按真实目录解析，符号链接不能绕过范围检查；目录不存在、不可用或超出允许范围时停止派发并说明原因，不切换目录或另选 worker。配置不是原生文件权限，不会作为根目录列表透传给 Codex。新 worker 的默认目录规则见[任务与执行](tasks-and-workers.md#工作目录)。

设置页区分功能启用、正在连接、已连接和连接或恢复失败。启动连接在应用就绪后后台进行，不阻塞插件初始化；任务执行需要连接时会等待同一连接操作。连接失败保留已启用设置并显示错误，可点击“重新连接 Codex”重试，或刷新状态查看结果。`codexWorkerEnabled` 是连接与任务操作的唯一配置；`codexConnect`、`codexMutations`、`routingResume`、`routingFork` 及对应环境变量不再控制这些操作，operator 也不能单独覆盖四项派生开关。Worker 高级设置包含统一恢复阈值、歧义分差和每页候选上限 `routeCandidateLimit`（默认 50，范围 1–200），以及时间预算与租约参数。

Codex 连接在 `initialize` 握手中默认声明 `experimentalApi: true`，以支持 worker 请求使用的 `runtimeWorkspaceRoots`。工作区根目录与 App Server 权限策略共同确定文件访问范围；实验能力声明不会开启 Codex worker、放宽审批或授予文件权限。Cordis 配置 `experimentalCodexApi` 优先于环境变量 `DSH_PERSONAL_AGENT_CODEX_EXPERIMENTAL`，未配置时为 `true`。显式关闭后，当前 CLI 会拒绝包含工作区根目录的新建、分叉和首轮请求；正常 worker 执行应保持开启。此项不是设置页中保存的运行偏好，修改后需重载插件并重新建立连接。

`workerModelPolicies` 按 `dsh_standard`、`dsh_cordis`、`codex` 引用模型策略；模型策略通过表单配置名称、worker 类型、提供方、模型 ID 和推理等级。重命名或移除策略时维护引用，Host 校验适用后端。`workerCapabilities` 按后端声明可满足的能力，可通过 Cordis 配置或运行设置接口配置。允许的 DSH preset 显示中文名称和用途说明。

配置加载支持将 `workerRules` 和 `defaultDshPreset` 转换为默认优先级及模型引用，运行时不执行关键词规则。无法表达的条件、能力限制和冲突在设置页显示提示，原值保存在 `settings.worker_selection_migrated` 事件的 `previous` 中。核对默认 worker、允许的 DSH 模式及模型策略后再处理提示；有条件规则的能力限制不会自动扩大成后端通用能力。

| 后台任务 | 默认设置 |
| --- | --- |
| 启动历史同步 | 开启；等待初始化和 `appReady` 后运行一次 |
| 周期历史同步 | 开启；每 15 分钟 |
| 默认查询范围 | 最近 30 天有消息活动的任务；不限制历史导入 |
| 热正文、候选复核、容量 | 90 天、90 天、10 GiB；不自动永久删除 |
| 后台默认语言 | 下拉选择简体中文 `zh-CN` 或英文 `en`，默认简体中文；主会话不读取 |
| Worker lease heartbeat | 开启；每 30 秒 |
| Inbox 自动重试 | 开启；每 30 秒，每批最多 100 条 |
| 记忆提炼 | 开启；每 5 分钟，每次最多 12 个任务处理批次，最多重试 3 次；每次模型请求默认 10 分钟 |
| 历史归档 | 开启；每天 |
| 数据库备份 | 开启；每天，保留 14 份 |

后台默认语言用于任务标题、概述和记忆等可读内容。专有名、结构字段、ID、枚举、路径、代码和精确引文保留原样。该设置只追加模型指令，不执行语言检测、翻译或语言重试；主会话跟随对话语言。

记忆提炼有独立的 `memoryExtractionBudgetMs` 时限（默认 `600000` 毫秒），任务关联仍使用 `analysisBudgetMs`（默认 `120000` 毫秒）。`analysisInputChars` 和 `analysisOutputChars` 分别限制每次分析的序列化输入和模型输出。修改后的参数供下次提炼采用，正在执行的请求按开始时的配置收尾。

运行状态列表同时显示历史导入、记忆提炼和 Inbox 的已处理数量。历史同步完成后触发的提炼单独记录状态；提炼失败不会把已成功的历史同步标记为失败。关闭定时触发不会关闭执行验收、恢复对账或备份校验。

## 主会话维护

“主会话名称”默认“鲸鱼娘”，编辑后自动保存并设置原生 Session 标题，相同名称不重复写入事件。名称不能为空，最多 48 个 UTF-8 字节（约 16 个汉字），为归档后缀保留空间。

点击“清空主会话历史”并确认后，插件暂停微信派发，归档旧 Session，完成旧会话有效消息与工具结果的同步，再建立空白主会话。内部上下文排队事件和私有推理不导入记忆。旧会话按“当前名称-废弃会话-1、2、3…”连续编号，新主会话保持设置中的名称。编号跨重启和初始化记忆保留，修改名称不重置编号；失败重试复用预留编号。

清空保留记忆、实体、关系、任务、运行设置、微信登录及本人身份。旧原生 Session 文件保留并归档，作为记忆来源可追溯。空白主会话若被原生新会话界面切到全局默认模式，插件会在接入前恢复标准模式；已经开始过轮次的模式冲突仍明确报错。新会话使用标准模式和当前默认模型，只排入一份助理说明，没有旧对话。微信自动切换到新会话及新事件观察位置，旧输入隔离，尚未发送的旧输出取消，结果未知的发送仍保留核对记录；不需要重新扫码。

主会话正在运行或微信正在扫码时不能清空。操作进度由 Host 持久保存，关闭设置页不会取消；退出 App 后中断的操作需要在设置中重试。切换前失败时恢复旧标题与归档状态，保持原绑定；若恢复本身失败，页面保留错误并允许重试。成功切换后的微信重连错误单独展示，不重复清空。此操作与“初始化记忆”不同：它不删除插件记忆数据，也不开放给模型工具或微信命令。

## 初始化记忆

在私人助理 → 记忆系统 → 索引与记忆维护中点击“初始化记忆”，确认清理范围后提交。清理会删除插件全部经历、记忆、实体、关系、任务与执行，以及关联的 Codex 审批与收发队列、路由记录、租约与恢复状态、工作区基线、产物记录、用量、同步游标、后台执行记录和托管数据库备份。表结构、运行配置、功能开关及微信的账号授权、独立收发队列与互动记录保留；私人助理主会话绑定恢复为同一个原生 Session，主会话归档编号及清理状态保留。微信先暂停并等待在途操作，初始化结束后按开关恢复。原始 DSH/Codex Session、工作区及实际产物文件、非托管备份不在清理范围内。

初始化先取消排队查询、终止并等待查询线程回收，停止并等待历史读取和分析子会话，排空已接受的请求并关闭 Codex 接收连接，再以事务清空本地数据，按当前 Codex 开关和读取预算重新导入一次并重建索引。历史读取关闭时跳过导入；候选记忆由后续定时或手动提炼逐批生成，不会恢复原任务或重跑旧执行。原先已连接的 Codex 在清理后重新连接。配置的定时任务在初始化期间跳过触发，完成后恢复。仍有执行中或待对账任务时，必须先结束并对账；初始化不会通过删除账本掩盖未知执行结果。

操作提交即返回，页面展示等待在途操作、清理、导入和索引阶段，并禁用重复操作。关闭、隐藏或重开记忆页面不会取消 Host 操作；重开后从 Host 恢复状态。进度和结果记录在 `background_job_status` 的 `memory-initialization` 项，设置页的定时任务列表不展示此手动操作。事务失败保留原记录；备份文件清理不随 SQL 回滚恢复。已清空后导入失败会单独提示，可处理错误后重新初始化。Host 中断后显示未完成状态，不自动继续破坏性清理。

## Inbox 与备份

Codex 通知、审批请求和响应先写入 Inbox，再由投影逻辑处理。失败记录会保留错误和重试次数；关闭自动重试不会停止新通知投影。耗尽重试后，operator 检查来源和执行状态，再通过认证 `/api/personal-agent/operate` 使用 `action: "retry_inbox"` 与对应 `sourceKey` 重置单条记录。该操作不会授予审批。

`backup` 创建受管理的 SQLite 备份，并写入含文件名、大小、SHA-256 和创建时间的 manifest。`verify_backup` 只接受配置备份目录内的插件管理备份，并检查 manifest、哈希和 SQLite integrity。自动轮换保留配置数量；独立人工备份不参与轮换。

## 任务状态与数据位置

私人助理会话中的“记忆提炼”入口显示后台运行状态，点击展开失败执行记录、当前错误及原生子会话日志；具体状态和更新方式见[记忆管理](history-and-knowledge.md#记忆管理)。任务与执行记录侧栏使用当前皮肤的详情面板样式。定时开关不影响正在收尾的提炼，立即提炼与重试失败位于提炼记录页。

任务面板展示 Task、worker、验收和执行用量统计。当前验收条件没有结果时计为待验收。缺少价格数据时不报告费用；Codex 累积用量不冒充单次执行费用。

只读查询使用惰性启动的单个线程。Cordis 配置 `readQueryQueueLimit` 默认 `32`，包含执行中和排队请求；`readQueryTimeoutMs` 默认 `30000` 毫秒，包含线程启动与排队时间；两项均须为正整数，修改后重载插件。超限返回忙碌提示，超时返回调整筛选范围或时间预算的提示。关闭页面会取消已断开的 HTTP 查询，工具执行取消会取消对应查询；不会自动重试查询或转回 Host 同步执行。

本地数据默认位于 `~/.dsh/personal-agent-core`。可通过 Cordis Config 配置 `dataDir`、`databasePath`、`backupDir`、`codexHome` 和 `codexSocketPath`。工作区根目录必须使用绝对路径。

## 数据兼容与加载故障

当前 SQLite `user_version` 为 3。首次打开空数据库时，Host 使用当前 `schema.sql` 和 `lib/wechat-schema.sql` 创建表并设置版本；已有版本 1、2 的库追加当前表后保留数据。版本值由 Host 管理，不能通过手动修改版本号使不兼容的库变为可用。

已有业务库的版本不受支持时，插件拒绝加载且不自动清空；设置页的“初始化记忆”需要服务已正常加载，不能修复此类启动失败。先正常退出加载该库的 Host，保留数据库及其 WAL/SHM、托管备份和运行配置，再按实际结构安排离线初始化。离线处理须明确记录清理范围、保留并恢复配置、功能开关、主会话绑定及适用的微信状态；原生 Session、工作区和 Harness 凭证不属于插件库重建范围。当前没有面向任意不支持结构的一键迁移入口。

日常清理使用[初始化记忆](#初始化记忆)，只清空对话使用[主会话维护](#主会话维护)。重新导入完成仅表示原文已暂存，归属分析和记忆提炼继续按后台调度处理，状态见[历史与记忆](history-and-knowledge.md)。

## 微信接入

设置 → 私人助理 → 微信接入提供开关、扫码登录、扫码身份核验、打开共享主会话、队列处理及高级限制。微信默认关闭，远程审批也默认关闭；接入与恢复步骤见[微信互通](wechat.md)。
