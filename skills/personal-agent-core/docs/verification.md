# 验证

## 评测集与质量基线

[评测说明](../test/evaluation/README.md)统一维护评测文档、纯合成来源、金标准、生产检索评分器、隔离模型探针及基线结果。`npm run test:evaluation` 已接入插件检查，验证分组、精确引文、评分分母与生产查询的候选/有效期/冷热正文行为。原生模型测量使用独立 profile 中的真实主会话和 worker，不向日常记忆库、主会话、微信或已有用户 worker 写入测试数据。流程故障先修复，再冻结受影响测量；模型质量与性能失败完整保留。

## 插件检查

在 `personal-agent-core` 目录运行：

```sh
npm run check
```

该命令检查入口语法，并运行导入、会话任务、提炼、查询、存储、设置、worker、审批和恢复测试。任务模型覆盖非连续与共享归属、完整发布、版本竞态、活动时间空隙、原文范围、空结果、实体单独输出、发布失败、冷热原文读取、索引重建、备份、删除排除和失败游标分页。`test/task-model-review.test.js` 进一步覆盖模型伪造确认状态、提炼准备失败、状态版本更新、删除期间的旧分析回写、未归属原文的筛选和分页、新上下文重新判断 unresolved、跨页图关系、标点查询，以及 Codex 写入失败后的游标恢复。队列测试验证已耗尽重试的旧作业不阻塞其他批次、本轮新失败及时停止、处理数量累加、过时结果不污染新版本错误，非法任务合并修正后保留原任务 ID 和来源，以及删除任务后剩余消息不会受旧重试上限阻塞。无效 JSON 测试通过实际分析解析与运行记录验证当前块恢复、已验证块复用和达到上限时无部分写入。Canvas 测试覆盖默认节点/关系、局部放大、曲线路径命中、节点和关系取消选中、运动暂停、拖动与资源清理；详情测试覆盖取消后的旧响应拒绝回写和任务关联只读说明；模拟 Canvas 不能代替实际页面检查。

```sh
node test/history.perf.js
```

性能基准使用合成历史，测量导入耗时和事件循环间隙，不包含模型或网络延迟，也不承诺真实数据的固定性能。

归属恢复测试使用四条输入消息与遗漏一条的模型响应，核对诊断中的缺失 ID、重试上限、无效草稿不改变先前状态，以及修正后一次发布完整归属。真实 Harness 探针同时核对失败记录和恢复结果。精确引用检查覆盖记忆与实体，保留标点、空白和 Markdown 差异，不通过改写原文放宽校验。别名恢复测试覆盖无来源别名在当前分块重试、有效分块复用，以及提炼先于未分析会话执行；字段测试覆盖重复规范名、未声明实体引用和无效记录字段。

Codex 开关联动回归使用 `node --test test/codex-enablement.test.js`，覆盖实验能力默认开启但 worker 默认关闭、显式配置与环境变量优先级、已保存开启状态的权限修复、初始化不连接、开关与权限原子提交、失败回退、允许 preset 下的关闭回退、无可用回退时保持原设置、并发连接合并、错误保留与重试、关闭期间连接排空，以及活动任务和模型越权保护。`test/adapter.test.js` 的 UDS 服务按握手能力校验 `runtimeWorkspaceRoots`，验证默认配置能创建会话且未授权的写操作仍被拒绝；同时覆盖 malformed RPC envelope 不抛出、不写入 Inbox、不触发通知或审批，非法响应不会结算 pending 请求，Inbox 写入失败会阻止分发，以及远端 method 不能触发本地生命周期事件。连接与执行使用隔离适配器和临时数据，不向日常 Codex 会话发送任务。

检索性能回归由 `test/evaluation/retrieval-performance.test.js` 检查单次全文扫描、共享消息计数、前五条片段顺序、补充分页、归档错误与修改后的新请求。`query-thread-equivalence.js` 对比同步业务视图与真实线程的完整响应；`retrieval-equivalence.js` 对冻结源码验证检索语义。`test/query-reader.test.js` 和 `test/evaluation/query-thread.test.js` 验证队列上限、启动与排队超时、取消、异常退出、终止失败、只读连接、快照一致性与写后可见性；初始化测试验证清空前关闭连接，回收失败不清库或重开连接。规模、Host 响应性、资源和真实 Harness 工具测量统一见[B0 性能基线](../test/evaluation/README.md#b0-性能基线)。数据库定义未改变，不需要索引重建或数据迁移。

## Harness 集成探针

`test/harness/probe.js` 和 `test/harness/expected.json` 用于 keyless Harness 集成检查。探针使用实际 Agent loop、Session、工具派发和 DSH spawn provider，通过 `pnpm dsh web` 的受支持启动方式加载测试 overlay；它不属于插件 bundle。运行器提供独立的 `DSH_REVIEW_CHECKOUT`、`DSH_REVIEW_ROOT` 和 `DSH_HOME=$DSH_REVIEW_ROOT/harness-home`，并装载插件和 probe overlay 后调用认证 endpoint。插件数据目录与 Codex 目录也放在该临时根目录内；探针在缺少独立 DSH home 时拒绝启动，避免测试会话或设置进入日常环境。

集成探针验证 Harness 装配、受管 internal 执行、DSH worker、记忆提炼运行记录和数据投影，验证实际模型通道返回的候选完成来源校验、人工确认后可召回且无关词查询不命中，并检查提炼子会话的原生身份及协调会话没有 turn。夹具预置与模型规范名相撞的其他实体别名，核对提炼仍绑定正确实体；普通经历与会话任务的提炼都先返回删去反引号的无效引用，再依据重试诊断返回精确引用，确认失败与成功均有执行记录，任务版本只在成功后标记完成。任务归属与提炼各先返回未闭合 JSON，再按格式诊断返回有效输出，核对失败与成功记录及最终任务版本。提炼夹具额外返回实体确认状态，核对 Host 仍保存候选；补充检索夹具核对未归属来源的会话筛选和分页。独立批次夹具使用真实模型通道验证旧失败作业不阻塞两个有效任务、非法整合经过诊断后保留已发布 ID，过时提炼留下失败日志但不修改新版本错误，以及删除任务后剩余消息可继续归属。历史检索验证空任务账本不影响历史搜索，并确认原文命中归组到稳定会话任务，再读取对应来源。探针还初始化自己独立的记忆库，核对任务、经历和图谱清空、配置及主会话绑定保留，并确认原生分析与 worker 日志仍存在。它不验证付费模型语义质量、真实 Codex 写操作或用户当前 Desktop 实例。报告运行结果时应指出实际加载的插件路径和 profile。

## 执行选择与续接

项目关联回归核对 DSH/Codex 新任务在指定新目录派发、历史来源保留，以及显式项目冲突不留下新 Task。`test/evaluation/check-tool-output.js CHECKOUT NEW_OUTPUT_DIRECTORY` 通过真实 Harness 工具执行管线检查对象、空列表和 `null`；旧对象限定作为负向对照，生产返回声明必须接收合法结果。

`test/dsh-startup.test.js` 验证原生名称拒绝后同一 Task 可重试、失败记录不会被恢复成虚假会话、真实缺失会话仍阻塞，以及未知启动保留租约。受理后关联写入失败的用例核对原生终态补回关联与结果；身份冲突不生成证据或完成执行。

`test/execution-flow.test.js` 覆盖历史 Codex 工作在尚无 Task 时保留原 Thread、显式原生身份早于导入、忙碌阻塞、已完成 Task 的关联后续工作、候选覆盖不足、三种默认选择、非法参数组合、旧配置迁移及一次迁移记录。并发测试使用受控屏障核对已有 Task 的首个 worker 和原会话续接均只派发一次；覆盖未知创建无原生身份时阻塞、查询后目标变化、跨调用者请求 ID 隔离和主会话直接执行保留原 worker 关联。语义响应缺少候选或字段无效时拒绝派发；投影测试对比完整重放和检查点后缀恢复。边界用例覆盖显式来源在分页前筛选、冲突 ID 拒绝、历史目标不改投 Task 的其他会话、截断候选不自动决定目标、新建 Codex 会话与新建 Task 解耦、历史分叉关联保留、替代会话创建失败后仍可续接原会话，以及 DSH 元数据写入失败后的事务回滚和租约释放。Codex 与 internal 会话关联写入失败时，执行和 Outbox 一起回滚并释放租约；远端回复后的本地写入失败则保存未知状态，不重发。恢复测试核对 executor Thread、精确 turn 和通知线程身份，缺失回执不使用最新轮次替代；取消创建 Thread 后不启动 turn。冷会话有待处理输入时，检查在恢复 Agent 前阻塞。Codex 终止通知测试验证结果证据与当前 Task/Execution 绑定、多条件待验收、逐项完成、重复终止不覆盖已通过结果，以及旧终止证据可以直接读取而历史消息 ID 仍被拒绝。通知测试验证有界批次越过未结束任务、多子会话回执经检查点恢复后不重复通知、空闲不获取主会话、旧绑定的未知交付不转投新主会话，以及未知通知不阻塞后续结果。主会话清理测试验证获取会话期间开始清理会延后未发送通知，已提交的结果则先落盘再归档。

`/api/personal-agent-flow-probe` 使用 `test/harness/flow-probe.js` 和 `flow-expected.json`，在真实 Harness Agent loop 中验证释放后的同树子会话按原 ID 续接、普通 DSH 会话保留原 PTC 模式、其他代理树拒绝接管、重复请求去重、多个子会话通知均保留且结果仅交付一次、已有 worker 的 Task 在主会话直接执行时保留原执行关联且不新增子会话，以及验收保持待核实。续接子会话使用原生结果通知，普通会话及同步返回之外的结果使用插件持久通知。测试模型为确定性夹具；Codex 分支通过协议适配测试验证，没有向用户真实 Thread 发送测试任务。

目录回归覆盖活跃与冷恢复的普通会话和子会话、只读位置记录、无效目录拒绝、切换失败时的租约和临时监听器释放，以及准备期间目录变化时不恢复旧目录。真实 flow probe 从主会话目录 A 创建目录 B 的 worker，确认会话头仍为 A 时可在 B 续接；再将同一冷子会话切换到 C 并恢复续接。普通会话连续变更 C、D 后沿用 D。探针同时核对原 Session ID、Task 项目归属、历史执行位置，以及 C 上的 baseline 和写租约。

Codex 目录回归覆盖旧目录已经不存在时指定新目录仍续接同一 Thread、文件路径和不存在的目标目录在恢复前拒绝、Execution 与租约及 baseline 位置一致、原生响应中的当前目录不同、显式目录切换、Task 项目归属保留和每次执行位置。分叉测试核对完整根目录、已完成边界、延后目标执行及来源身份；还覆盖不可直接接收输入、原生错误状态、空会话、关闭后失效、取消目标多义、断线后的租约保护，以及重连订阅期间原 turn 已完成的情况。原生模型探针可用 `input.operationsAudit: true` 验证新建、续接、多根目录分叉、来源历史不变及断线后继续同一 Thread，全部使用独立数据目录。

设置与插件入口测试覆盖后台语言选项校验、跨重启持久化、历史同步与提炼的状态隔离，以及关闭期间已接收操作的排空。

设置页检查默认优先级的三种选择、Codex 开关联动、即时保存、重载后保持、保存失败反馈、键盘操作及窄窗口明暗主题。查看并消除旧规则迁移警告前，先核对所保留的原配置。隔离 profile 的通过结果不代表用户 Desktop 已重新加载插件；实际生效环境单独确认。

## 提炼状态与记录

在隔离的 Web profile 使用 probe 模型并提供一条可提炼经历，从记忆提炼记录页触发提炼，核对主会话状态与执行记录在运行和完成后自动更新。`/api/personal-agent-review-hold` 的 POST/DELETE 可在集成夹具中暂停/释放模型输出，便于检查运行状态；此路由只由测试探针注册。核对普通会话列表不出现提炼记录，日志按钮打开原生子会话，失败前未创建子会话的记录不提供日志按钮，并检查窄屏、明暗主题和退出后的轮询清理。

## 记忆界面

在实际加载本插件的 Harness 私人助理会话中打开记忆，核对桌面左右面板、390px 窄屏抽屉、长详情滚动、查询/空结果/加载更多、节点选择、旋转和缩放、关闭后的焦点恢复，以及人物动画和减少动态效果。原文分页可使用探针隔离库中的 105 条“待归属分页验证”消息：开启原文搜索后首批为 100 条，加载更多得到 105 条不重复记录，前页保留，末页来源能打开详情且无继续加载按钮；再检查窄屏详情可读。真实库缺少实体或关系时，应明确这部分未获得真实数据验证；模拟绘图测试只覆盖数据映射和资源生命周期。

## 微信互通

`node --test test/wechat.test.js` 使用隔离库与 loopback iLink，验证唯一主会话、扫码账号精确匹配、重复输入、最终正文、稳定分段、发送状态、重试预算、互动竞争、严格答案语法、Codex epoch、账号锁、本人身份变更及备份 hold。回归用例还覆盖空闲通道不恢复 Agent、已提交答复补发、归档及缺失会话拒绝、待处理上下文一次去重、超大拉取的断点接收、满队列排空、超容量答复续传、撤回与凭证写入的竞争、主会话初始化持久化失败、混合来源的停止保护、错误状态保留、完整审批范围，以及停止时的互动清理。组合场景核对分段配置变更后的续传、停止指令记录失败、审批决定写入失败、跨实例账号占用、自动身份核验期间持锁、二维码完成和失败后的释放，以及连接前失败不耗尽互动额度。插件入口测试验证初始化失败不遗留 projection，卸载等待延迟注册的 handle 释放。

同一 Harness probe overlay 注册 `/api/personal-agent-wechat-probe`，经有效连接 cookie 调用。`test/harness/wechat-probe.js` 核对微信输入与桌面追问共享原生 Session，重复消息只入站一次，并从真实 Agent loop 调用原生问题及包含完整调用参数的一次性审批，注入决定写入失败后核对原生结果为 unavailable，再与 `wechat-expected.json` 比较。腾讯登录和发送使用夹具，不会发送真实微信。

在真实设置页检查默认关闭、扫码身份状态、账号标识折叠区、共享主会话提示、打开主会话、队列操作、明暗主题、窄窗口和键盘焦点。真机扫码、腾讯资格、互动额度及手机送达需要另行核对，不能由自动化夹具推断。

主会话身份回归检查普通会话记忆写入后的来源消息、原分类和工作区限制；旧角色标记与任务记录不授予助理身份。真实 Harness 探针确认角色命令未注册、主会话选择请求被拒绝、普通会话记忆来源可追溯，且桌面与微信恢复同一会话。设置页检查共享提示与“打开主会话”，不显示候选选择和绑定按钮。
