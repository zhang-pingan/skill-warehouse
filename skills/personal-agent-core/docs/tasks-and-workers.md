# 任务与执行

本文说明消息如何匹配已有工作、继续原会话或选择新 worker，以及结果如何回到主会话并完成验收。默认 worker 和模型策略见[设置与运维](settings-and-operations.md)，未知执行的处理权限见[安全与恢复](security-and-recovery.md#未知执行)，检查方法见[验证](verification.md#执行选择与续接)。

## 任务账本

Task 表示跨 Session 的持久目标，可包含有依赖关系的 TaskStep；Execution 表示一次执行尝试。新建 Task、新建 Execution 和新建原生会话是三个独立动作。历史会话任务记录过去的工作，导入和检索不会自动创建可执行 Task。

worker turn 成功只结束一次 Execution。Task 每个当前验收条件都必须有通过结果，并引用属于同一 Task 和 Execution 的证据。新尝试不继承旧验收；步骤依赖和未解决的写入恢复状态也会阻止完成。

## 消息执行流程

主会话先理解当前请求：问答、进度查询和合适的简短工作直接处理；需要持久管理的直接工作使用 `execute(worker: "internal")` 记录开始，实际完成后调用 `finish_execution`。直接执行仍先匹配管理目标并检查未结束执行，但不恢复或派发该 Task 原有的外部 worker；原执行会话关联保留供后续委派。需要委派时按以下顺序执行。

1. 联合查询执行账本 Task 与 DSH/Codex 历史 `session_tasks`，不先按 worker 或主会话默认目录过滤。已有稳定关联合并为同一候选；同一原生会话中的不同历史目标仍各自保留。
2. 核对目标、来源版本、过程摘要和消息证据。语义关联分析只比较工作目标，不选择后端；每个输入候选必须返回一次判断，不兼容候选也不能省略，输出预算通过缩短理由满足。匹配采用统一阈值及歧义分差；多个候选、历史截断、待归属或读取失败分别报告。必要时通过 `memory_get` 补读原文。
3. 有原会话时，先验证其身份、运行状态、归属及权限。可继续则保持原 Session/Thread、preset 和模型。DSH 与 Codex 默认沿用原会话当前有效目录；明确指定目录时在同一会话内切换。历史任务尚无 Task 时建立管理关联；正式完成的 Task 产生关联后续 Task，但仍可沿用原会话。
4. 需要新 worker 时才解析模型的创造模式选择或配置默认值。执行前重验会话与目录，并登记请求、Execution 和工作区租约后派发。
5. 保存本次结果及来源范围，交付主会话。主会话读取证据、验证各项验收条件并汇报；未通过时继续跟踪剩余工作。

`route` 预览和 `execute` 使用同一目标发现、原生状态检查和新建策略。`taskId` 指定执行账本任务；`sessionTaskId` 指定历史目标；`sessionId` 与 `sourceSystem` 可指定尚未导入的原生会话。来源筛选在分页前执行；同时指定的身份必须对应同一工作，不能以一个 ID 的匹配忽略另一个 ID。显式历史目标保留其原会话。自动匹配的候选页被截断时，需要继续分页补查并指定目标，不能把当前页唯一候选视为全局唯一。目标不明确时返回澄清候选。`intent: "continue"` 找不到目标时阻塞；`intent: "new"` 说明是新目标，但不会自行覆盖已经匹配到的原会话。

`newTask` 只新建管理记录。已有未完成 Task 更换或分叉原生会话时保持同一 Task，除非显式请求新管理记录；Codex 替代会话建立成功前保留原执行关联，明确的创建失败后仍可继续原会话；从未分配执行会话的已有 Task 也可以创建自己的首个 worker。更换原生会话使用 `sessionAction: "new"`，Codex 分叉使用 `sessionAction: "fork"`；主会话工具必须提供 `sessionChangeQuote`，精确引用当前用户要求。模型普通的 worker 选择不能改变已有会话。DSH 执行入口不支持从任意指定 Session 分叉，会明确拒绝；可继续原会话，或由用户明确要求新会话。没有自动迁移后端、自动分叉已完成工作或忙碌时另开 worker 的行为。

执行工具使用 `newTask` 和 `sessionAction` 分别表达管理记录与执行会话的变化，不接受 `forceNew`。Host 服务仍识别 `forceFork` 兼容输入，公开工具调用使用 `sessionAction: "fork"`；相同的来源、用户原文与权限检查仍适用。

新建管理 Task 且新建 worker 时，项目归属从经过校验的本次工作目录取得，历史目标保留为来源参考，不把旧项目强加给新目录。显式传入的项目与目录冲突时，在创建 Task 前拒绝。继续或分叉原会话仍保留原项目归属。

同一 Task 首次分配 worker 和原会话续接都占用任务派发入口。目标在查询后发生变化时重新查询；已有运行中或结果未知的执行时不新建替代 worker。请求去重按调用者会话与权限范围隔离，同一范围重复请求返回原执行，不同范围使用相同 `requestId` 不共享执行。

## 原会话续接

DSH 与 Codex 采用同一目录规则：续接前读取原生会话当前有效目录；未指定目录时沿用，指定后验证并在同一会话中切换；每次执行记录实际采用的目录，相应租约和文件快照使用同一位置。历史目录仅作线索，不因它与当前目录不同而拒绝续接。两种后端共用目录存在性和类型校验；已有 Task 的项目归属保持不变。

DSH 普通会话通过原生 Session controller 恢复和接收输入；同一代理树内的 continuable 子会话通过原生 subagent 消息入口恢复原 ID。已释放子会话保留原始历史和配置。其他主会话树的子会话、归档会话、缺失数据和正在运行或排队的会话会返回阻塞原因。清空主会话不会伪造旧子会话的树归属。

### 工作目录

DSH 与 Codex worker 在新建、续接、分叉和显式切换目录时使用同一份可选 `allowedWorkspaceRoots`。空列表不增加插件限制，非空列表要求本次采用的真实目录位于允许的根目录或其子目录。普通调用者原有的工作区约束仍然生效。白名单在原生执行前检查，设置不能让不存在的目录或不可用会话变为可执行，也不决定原生文件读写权限。

新建 worker 且未提供 `workspacePath` 时，不继承主会话目录：DSH 调用 `workspaceController.initializeDefault()` 取得框架默认工作区；该工作区不可用时要求明确指定目录。Codex 通过 App Server `config/read` 和 `configRequirements/read` 读取桌面端无项目目录配置，受管 `application.storage.projectlessWorkspaceRoot` 优先于 `desktop.projectlessWorkspaceRoot`；未配置时按当前用户主目录拼接 `Documents/Codex`。App Server 没有创建桌面默认工作区的专用 RPC，插件按桌面规则创建 `根目录/YYYY-MM-DD/任务名`，日期采用本机日期，任务名取前六个英文或数字单词、最多 80 字符，无匹配词时用 `new-chat`；重名分配独立目录，并创建 `outputs` 和 `work` 子目录。创建前检查允许范围，不能通过默认目录规则绕过白名单。Codex 新会话的 `cwd` 和 `runtimeWorkspaceRoots: [cwd]` 使用该任务目录，不扩大到白名单的所有根目录。已有会话续接从原生会话读取当前有效目录，不重新分配默认目录。

DSH 当前工作目录由原生 `workingDirectory` 服务维护。预检读取活跃会话状态，冷会话读取原生 projection，按最后一次目录变更确定有效目录；不把会话头中的初始目录或导入缓存当作当前目录。`route` 只读预览不恢复 Agent 或切换目录。续接时省略 `workspacePath` 沿用当前有效目录；显式提供时先验证目录存在、可选白名单及调用者范围，再通过原生服务切换后派发输入。目录不同不会触发新会话。准备期间有效目录发生变化且请求未指定目录时，停止本次派发并要求重新执行，不切回旧目录；切换失败同样停止派发。明确未派发且原生清理正常时释放本次写租约，原生回滚失败或结果未知时保留恢复保护。未完成目录准备的尝试不记录为已采用该目录。

每次 DSH 执行（包括只读）记录采用的目录位置，最近执行目录从这些记录派生；旧导入记录仍可提供历史目录线索，实际续接始终复查原生状态。切换目录不改变 Task 的项目归属，本次写租约与 baseline 使用新目录，先前执行记录保留原位置。目录变更过程使用 DSH 原生事件，插件不另建当前目录状态或重复记录变更历史；目录切换不会扩大沙箱权限。

Codex 历史 Thread 经 `thread/read` 检查后，在当前连接调用 `thread/resume` 订阅并获取有效设置，再开始新轮次，不要求之前由私人助理创建。即使本连接曾加载过该 Thread，也会在新轮次前刷新设置；`route` 预览仅查询，不恢复会话。续接需要启用 Codex worker 并连接服务，配置白名单时，工作目录须在允许列表内。新建、续接和明确分叉权限随该开关一起启用。已有 Task 的首个 Codex Thread、显式新建 Thread 分别按新建权限检查；分叉按分叉权限检查，不以 Task 是否新建代替原生操作权限。忙碌会话返回等待；只有当前 adapter epoch、受管活动轮次、完整 baseline 和有效工作区写租约同时匹配时，纠正请求才可 steer。等待不会自动重发，状态变化后需重新执行该请求。

Codex 的 `thread/read.thread.cwd` 可能来自旧会话资料；执行使用 `thread/resume` 返回的顶层 `cwd`。省略 `workspacePath` 沿用该目录，显式目录通过 `turn/start.cwd` 交给原生会话；在派发前验证实际将采用的目录可用及允许范围；明确指定新目录时，不要求被替换的旧目录仍存在。本次 baseline、租约和 Execution 使用已确认的目录，最近执行目录由记录派生，Task 项目归属不随目录变更。插件不在续接 turn 中重设 `runtimeWorkspaceRoots`，附加目录由 Codex 维护。

Codex 分叉先读取来源的有效目录与完整工作区根目录，再以最近一个已完成的 turn 为边界调用 `thread/fork`，明确传入来源设置。分叉返回的新 Thread 必须不同于来源；若返回 `forkedFromId`，它必须指向请求来源。`deferGoalContinuation` 阻止继承目标在明确提交新轮次前自行继续。分叉后的首轮只传本次采用的目录，不把完整工作区根目录覆盖成单个目录；来源历史保留不变。

原生会话报告 `systemError` 或不能接收直接输入时停止派发；临时 `ephemeral` 会话不能作为持久 worker 续接。尚无持久轮次、不能读取历史的外部空会话需先在创建它的客户端开始会话，插件不会根据错误文字猜测可续接状态。归档来源由原生恢复接口拒绝，不会自动解归档或创建替代会话。

## 新建 worker

| 条件 | 选择 |
| --- | --- |
| 主会话模型理解为新建或维护 DSH 插件，且确需新建 worker | 同时指定 `worker: "dsh_subagent"`、`agentPreset: "cordis"` |
| 其他新建委派任务 | 同时省略 worker 和 preset，读取 `defaultWorkerPriority` |

默认优先级提供 DSH 标准模式、DSH 创造模式和开启 Codex 后的 Codex。Host 不按“插件”、`harness`、`preset`、`ptc` 等关键词选择后端，也没有 PTC 自动分支。已有 PTC 会话仍保留原模式。单纯咨询插件不必创建 worker。

Host 校验参数组合、允许模式、所需能力和模型策略。所选后端未启用、创造模式未加载或能力不满足时明确报错，不静默改用另一后端。配置与迁移见[设置与运维](settings-and-operations.md)。

DSH 启动受理后才发布 worker 的执行者关联。原生明确拒绝无效或重复名称时，本次尝试保留为失败，修正名称后可在同一 Task 重试，不会留下不存在的会话作为续接目标。其他启动失败可能发生在输入已接收之后，保持对账状态及工作区写入保护；取得身份、请求和 Execution 均匹配的原生终态后，才能恢复结果和缺失关联。已有执行者身份冲突时停止结算并显示待处理项。

## 结果、恢复与写入

工具结果支持对象、对象列表和 `null`。`list_steps` 没有步骤时返回空列表；`get_task`、`memory_get` 未找到记录时返回 `null`，主会话可据此继续查询。

DSH 与 Codex 的终止状态、结果和验收独立记录。DSH 输出范围绑定 Execution、请求 ID 和原生序号；Codex 绑定 Thread/turn。工具返回的续接决定使用完整 JSON 值，缺少的历史执行元数据显式为 `null`，不会在派发成功后被宿主拒收。Codex 终止通知包含绑定本次 Execution 的 `evidenceId`，并登记待验收项；重放相同通知不会覆盖已有验收结论。`get_task.verification` 返回 `criteria` 的 ID/正文及当前执行的 `evidenceIds`，已有终止结果也可从这里取得证据，无需等待历史提炼。验收使用这些证据 ID，不能使用 `history-message-*` 消息 ID，也不能以工作已完成代替逐项核实。主会话工具同步返回、原生子会话通知与持久通知队列协调去重。多个子会话的最新通知回执分别保留，检查点恢复后仍可识别。恢复检查按有界批次轮转，前面的长期运行任务不阻塞后面的已完成结果。主会话忙碌时通知进入原生输入队列；未交付结果在重启、执行事件或后台维护时核对，空闲且无待办时不恢复主会话。

通知提交结果未知时先核对原生日志和待处理输入；不能确认则留下待处理提示，停止自动重发，但不阻塞其他结果通知。通知已指向旧主会话而绑定发生变化时，不自动投递到新会话。清空主会话先等待正在交付的结果落盘，再归档旧会话；尚未提交的通知在清理期间暂停。工作结果保留在账本，验收仍待主会话核实。

受管 DSH、Codex 和 internal 写入共享 canonical workspace path 写租约，包括嵌套路径。可能修改文件的执行先保存 baseline，并通过 heartbeat 维护 lease。Execution 与原生请求记录在事务中准备；新 DSH worker 的执行者关联在原生受理后原子发布。派发前写入失败会撤销本次执行准备并释放租约，受理后的记账失败则保留对账状态。取消会阻止后续派发阶段，例如创建 Codex Thread 期间取消后保留已确认的 Thread，但不再启动 turn。取消是停止请求，不代表工作已静止；未知结果保留 `recovery_hold`。认证 operator 核对原生状态和工作区后才能解除保护。

Codex 回复中的 Thread 身份必须与请求相符，分叉必须返回新身份并通过来源检查，`turn/start` 必须返回 turn ID。收到回复后本地提交失败或回复身份无法确认时保留返回内容并标记未知，不作为明确拒绝重发。恢复只查询 Execution 的 executor Thread 和已记录的精确 turn；交互会话、分叉来源或最新的其他 turn 都不能代替缺失回执。无法确认的执行继续保留对账状态。取消操作同样要求唯一的 Codex executor Thread 和 turn；身份缺失或多义时不发送中断。连接丢失使运行中的执行进入对账并保留工作区保护；重连发现原 turn 仍在执行时，先重新订阅，再核对恢复响应中的同一个 turn，防止漏掉终止事件。
