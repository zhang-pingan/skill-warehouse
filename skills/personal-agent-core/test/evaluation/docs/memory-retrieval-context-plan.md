# 记忆检索与任务上下文优化方案

状态：第 1 项已完成，B0 可作为指标起点。检索、主会话问答、模型候选关联、30 次自主执行、原生压缩与重启、规模和增量写入测量已收齐，正式确认规则及样本量规划已固定。阻碍流程的已确认实现问题已修复，模型错误、上游失败、超时和性能弱项如实计入。当前结果、源码身份和范围以[基线报告](baseline-report.md)为准。保持检索结果不变的前置性能优化已实施并通过隔离服务和真实 Harness 工具验证，统一 B0 见[性能基线](../README.md#b0-性能基线)。日常 Desktop 的 Host 代码在重新加载插件后生效。第 2、3 项尚未开始；流程修复和前置性能工作不计为这两项优化实验。

## 目标与范围

本方案对应总体建议中的三项：1. 建立插件评测集与基线；2. 改进历史任务和记忆检索；3. 为主会话与 worker 按需准备任务上下文。目标是提高找回正确历史、继续正确任务和遵守历史约束的能力，同时控制延迟、模型用量和运行复杂度。序号不对应后续讨论中对第 3 项拆出的实现步骤。

本轮范围不包括新增主动任务、自动等待续接、经验学习或修改任务验收业务规则。既有验收流程和测试作为评测对象与回归保护保留。现状说明见[历史与记忆](../../../docs/history-and-knowledge.md)、[任务与执行](../../../docs/tasks-and-workers.md)及[验证](../../../docs/verification.md)。

## 执行顺序与阶段条件

严格串行执行，不同时开发或运行第 2、3 项的优化实验。每项内部也一次只执行一个实验，记录并处理完结果后才开始下一步。

1. 完成第 1 项，冻结数据、评分方式、比较条件和正向门槛，生成当前插件的可复现基线 B0。
2. 前置完成保持结果不变的性能优化，核对返回等价并复测查询、内存、启动和增量写入成本。将完整性能优化及其测量更新到唯一 B0，删除被替代的性能迭代记录，作为第 2 项对照。
3. 开展第 2 项。每次只改变一个可解释的因素，在隔离环境中验证，完整记录正向、负向及无法判断的结果。
4. 单次实验达到正向标准后，才将该项改动合入实际插件、完成运行验证并更新现状文档。确认实际运行版本就是通过评测的版本后，建立新的已应用基线，再做第 2 项的下一个实验。
5. 第 2 项至少有一项符合门槛的改动真实应用，相对 B0 有明确收益且无未处理回归，并达到本方案的停止条件后，冻结第 2 项最终版本 B2。前置性能收益不计作第 2 项通过的依据。
6. 重新测量 B2，作为第 3 项起点。随后用同样的逐步实验、记录、正向应用、复测流程执行第 3 项，直到难以再获得明显正向收益，形成最终版本 B3。

第 2 项若没有任何改动达到正向标准，维持已验证的前置性能版本，记录未通过原因；不得以“做过实验”代替阶段通过，也不得直接开始第 3 项。存在未解决回归、应用失败或证据不足时，同样不能跨阶段。

## 第 1 项：评测集与基线

### 用例与数据

首版使用纯合成数据，不读取真实会话正文或记忆作为评测输入。当前数据、评分器、运行入口和冻结规则由[评测说明](../README.md)维护。未来若加入脱敏历史或公开样例，须先确认使用范围；真实历史仅从一致性快照读取，实验数据不得写回日常记忆库或主会话，不得因整理评测而删除、重置或自动确认真实记忆。

首版包含 60 个合成来源族、300 题：探索集 36 族/180 题，验证集 12 族/60 题，封存集 12 族/60 题。来源族有独特主题但共享题型模板，同族五题相关，不是 300 个独立真实历史。下表列出完整评测要求；当前已测与仍未验证的部分在基线报告中区分。正式确认样本量按来源族方差、预设最小收益和检验功效确定，不能以重复运行代替独立样本，也不能从现有样本量推断已足以确认收益。

| 分组 | 必须验证的行为 |
| --- | --- |
| 历史召回 | 近期和较早任务、同义改写、中英文混合、代码标识符、原文命中、冷热正文 |
| 工作目标识别 | 同一会话多个任务、跨会话相似目标、跨项目同名任务、DSH 与 Codex 来源 |
| 续接决策 | 继续原会话、明确的新任务、多个候选应澄清、来源缺失或检索不完整应阻塞 |
| 时间与变化 | 后续纠正、有效期、已取代记录、先前与当前要求、跨会话证据组合 |
| 可信状态 | 候选不是事实、助手声称不是独立验证、无证据应拒答、来源中的指令不是授权 |
| 上下文传递 | 新 worker、原 worker 续接、主会话直接处理、历史约束遗漏、预算不足、过期摘要 |
| 不需要历史 | 普通知识问答或无关任务不混入记忆，不为读取页面或空闲轮询产生上下文 |
| 生命周期 | 请求重试、重启恢复、压缩后继续、任务版本变更、重复提交及启动性能 |

每条用例保存：稳定 ID、分组、请求与评测时点、数据和来源版本、预期任务/会话或应澄清/拒答的条件、必要证据、答案要点、必须遵守的约束、禁止结果及评分规则。预期结果由可核查的原文和事实确定，不能直接采用当前模型答案作为标准答案。

数据按原始会话、任务或项目来源族划分为探索集、验证集和封存确认集。同一来源的改写问题、相似副本及派生答案不能跨组泄漏。答案标签不进入记忆索引、模型输入或 worker 文件；上下文只包含评测时点可见的数据，不使用未来消息。

探索集用于定位问题和提出单步假设，验证集用于固定候选。封存确认集只用于候选的最终应用判断；一旦查看其细项，就转为回归集，不得继续拿它调参后声称独立确认。后续确认使用预先划分的未见样本；样本耗尽先补充并按同一规范标注，不降低标准。

### 指标与评分

| 指标 | 定义与用途 |
| --- | --- |
| Recall@10 / Recall@50 | 前 10/50 个候选覆盖必要证据或正确任务的比例，分别报告任务和证据召回；仅用于定位检索损失 |
| 工作目标决策正确率 | 正确选择任务和原会话，或在应澄清、阻塞、新建时给出正确决定的用例比例 |
| 有依据的回答通过率 | 答案满足预标注要点、来源足以支持关键结论、无不支持断言的用例比例；拒答用例单列 |
| 上下文约束遵守率 | 本次任务必须遵守的全部关键要求均满足的用例比例；另报每项约束命中情况 |
| 执行结果通过率 | 可验证产物与任务要求同时满足的用例比例，不以 worker 自报成功或 turn 成功代替 |
| 错误与回归 | 错误续接、跨项目污染、过期要求覆盖新要求、候选当作事实、来源指令被执行等分项计数 |
| 延迟与资源 | 检索耗时及端到端 p50/p95、模型调用次数、输入/输出 token、峰值内存、索引大小和更新成本 |
| 运行完整性 | 重复输入/执行数、原生日志可重建性、启动耗时和事件循环响应 |

评分先使用确定性断言、证据 ID 和产物检查；需要判断语义时采用固定评分准则、固定评判模型和隐藏 A/B 身份的判分，人工复核分歧、关键回归及改善样例。不能只靠实施候选的模型自行给分。无可靠价格时仅报告 token 和调用数，不推算费用；原生累计用量不能冒充本次消耗。

端到端评测分别覆盖主会话、DSH worker 和 Codex worker。不可用的真实后端明确标为未验证；mock 或 keyless 夹具只证明接口行为，不能代替实际模型的语义效果。

### 基线产物与冻结

B0 是接口、派发和证据链可用版本的指标基线。发现连接、派发、证据交付或验收等实现阻塞时先修复并验证，再冻结修复后版本；修复前记录保留为故障证据，不代替当前指标基线。低召回、回答错误、未及时完成及延迟等指标如实记录，不为取得基线分数提前实施第 2、3 项优化。冻结测量期间不改变生产源码。固定代码快照、Harness 版本、数据库快照和处理进度、模型与推理参数、提示词、权限、候选数量、上下文预算、时钟、超时和并发。分别记录冷缓存、热缓存与索引构建条件。模型用例至少进行 3 次重复；后续版本比较采用成对重复，以来源族为单位分析差异；随机种子可控则记录，不可控则明确说明。

当前[基线报告](baseline-report.md)和[结果目录](../results/b0-complete-2026-11-18/)保存执行前清单、语料/代码/评分哈希、生产源码快照、逐例结果、来源族区间和失败证据。检索、真实模型关联、主会话问答、自主派发、生命周期、规模与增量写入分别测量，不能互相替代。不同源码版本的复用须核验实际调用路径和模型可见输入，并保留原测量身份；提炼质量、桌面绘制及执行中强杀等范围未纳入本基线。

检索协议已在运行前冻结三次重复、固定查询词、10/50 候选、热/归档正文及首次/重复遍历；正向门槛和独立来源族的样本量规划见[确认设计](confirmation-design.md)。B0 完成后可开展隔离探索；正式应用仍须独立确认样本和成对验证，不能把当前小样本或重复次数当作功效保证。评测或评分工具发现缺陷时，修复后须将受影响的对照版与候选版一起重跑，并保留前次无效原因。

## 统一实验与应用规则

### 明显正向的判定

每个实验在执行前选定一个主指标和所属类型，登记预期收益、对照版本、样本量、统计方法、资源上限和保护指标。不能看到结果后换主指标、筛掉失败用例或下调门槛。下表为第 1 项需要确认并冻结的默认标准，不是已经测得的效果。

| 类型 | 默认正向标准 | 同时满足的条件 |
| --- | --- | --- |
| 质量优化 | 预选端到端质量主指标提高至少 5 个百分点，且成对差值的 95% 置信区间下界大于 0 | 其他关键质量指标下降不超过预定容差；默认容差 1 个百分点。p95 延迟和每请求平均 token 的增幅各不超过 10% |
| 效率优化 | 预选耗时或 token 指标降低至少 20%，且成对改善的 95% 置信区间下界大于 0 | 关键质量指标通过预先规定的非劣检验，默认容差 1 个百分点；其余资源指标不得超过预设上限 |

基线接近满分时，可以在第 1 项预先选择相对错误率降低至少 20% 作为质量主指标，仍需置信区间支持；不能在实验结果不达标后临时改用该口径。第 2 项优先用工作目标决策正确率或有依据的回答通过率，第 3 项优先用上下文约束遵守率或执行结果通过率。单独提高 Recall@K、增加候选数量或增加上下文长度，都不足以判定应用。

所有应用还要求：关键回归用例全部通过，未出现新增错误会话写入、权限扩大、候选自动确认或重复派发；各重要分组没有被总体均值掩盖的退化。超时、解析失败和拒绝请求计入失败及成本，不能从指标分母中删除。置信区间过宽或资源测量不完整时，结论为“证据不足”，不应用。

比较同时保留两组结果：候选相对当前已应用版本的单步增益，以及相对 B0/阶段起点的累计变化，防止多个小退化累积。频繁试验使用预先固定的确认次数和样本，不根据中途显著性提前结束；补测的次数与规则应提前登记。

### 单步执行流程

1. 在本阶段验证文档登记实验 ID、假设、唯一主要变量、对照版本及判定标准。实验代码只放在未被实际 profile 加载的隔离副本，使用独立数据目录。
2. 实现最小候选改动，跑针对性行为检查；数据、模型、评分方法等其他条件保持一致。确需多个联动改动才能工作的，应事先说明最小组合及不能拆分的原因。
3. 在同一数据快照上运行成对对照。记录真实命令、原始结果、失败、耗时、用量及环境差异，不能只保留最好的一次运行。
4. 写入验证文档，明确结论为“正向”“未达门槛”“负向”或“证据不足”。未达门槛和负向候选撤回；证据不足按预定补测规则处理。下一步必须从最近已应用的有效版本出发。
5. 正向候选通过封存样本确认、针对性回归和现有检查后，才合入实际插件。只合入本次已验证改动，不把其他未验证优化一起带入。
6. 确认 profile 实际解析目录、加载版本和有效配置；按需要执行受支持的构建、重载或重启，完成真实 Harness 入口的验证。另在隔离数据上复测合入后的同一版本；日常环境只做必要验证，不发送评测消息到本人微信或真实工作会话。
7. 将“候选通过”“源码合入”“运行时已应用”“应用后复测通过”分别记录。应用失败或复测回归时恢复上一有效版本和兼容配置，核对数据恢复方案；未完成处理前不开始下一实验。更新现状文档后，把通过的版本设为新基线。

### 何时停止

达到以下条件时结束当前阶段：当前已应用版本稳定；连续 3 个针对不同已知问题、预先登记且有充分测量的合理实验均未达到明显正向门槛；剩余候选的预期收益不足以覆盖实测延迟、成本或维护负担。阶段文档必须说明已经尝试和未继续尝试的方向。

配置故障、样本不足、后端不可用和预算耗尽属于“尚未验证/受阻”，不算收益饱和，也不算上述 3 次。测量显示所有剩余问题已达预先定义的质量目标时，也可以结束，但须提供完整分组结果。停止后保留最近已应用且通过复测的版本，不为完成清单而加入无收益改动。

## 第 2 项：检索优化

### 前置性能工作

B0 已包含单次全文扫描、批量活动计算、流式补充分页和独立只读查询线程，测量见[B0 性能基线](../README.md#b0-性能基线)。没有新增持久索引或跨请求缓存。完整历史范围、匹配、排序、总数、分页、片段、覆盖和来源校验保持原有语义；前置性能收益不计入第 2 项能力实验。

第 2 项实验前须核验插件源码与 B0 哈希一致；日常 Host 尚未重新加载时不能声称已运行新版本。查询线程隔离 CPU 扫描，不消除线性扫描、内存和结果传输成本，仍须纳入资源保护，不以截断历史加速。涉及候选集合、分词、查询改写或排序语义的变化属于第 2 项。

### 当前依据与目标

当前任务发现先取有限页候选，再由模型比较目标；较早目标和不同措辞可能需要额外分页。历史列表读取筛选后的任务集合，批量关联消息并单次扫描索引正文。模型重排不能补回未进入候选的内容。实现入口包括 [`execution-discovery.js`](../../../lib/execution-discovery.js)、[`session-history.js`](../../../lib/session-history.js)、[`fts.js`](../../../lib/fts.js) 和 [`service.js`](../../../lib/service.js)。这些是代码观察，不是已经测出的延迟或准确率结论。

目标是在固定资源预算内，更快地召回正确任务和支持回答的证据，并保持原有身份核验、覆盖状态、分页和歧义处理。先检索已有工作再选择 worker 的规则不变。

### 候选实验路线

下列是按成本安排的待验证方向，不是要求全部落地的功能清单。每个方向必须拆成独立实验；前一步的结果决定是否值得继续。

| 顺序 | 单步方向 | 需要证实的收益 |
| --- | --- | --- |
| 2A | 将正确的历史任务通过任务摘要/原文索引纳入候选，与现有账本候选去重排序 | 较早任务和非最近页目标的决策正确率提升 |
| 2B | 分别试验别名、时间/实体信息或查询词处理 | 同义请求和跨会话证据召回改善，项目与时间过滤不退化 |
| 2C | 试验有限候选的排序与已有模型关联分析的输入组织 | 同名目标或相似目标更易区分，模型调用和上下文成本可接受 |
| 2D | 仍有明确语义漏召回时，试验文字检索加可选向量召回 | 端到端质量增益足以覆盖 embedding、索引与维护成本 |

第 2 项不得同时改动记忆提炼、主会话工作说明或 worker 上下文组装，否则不能归因。向量方案不预先指定外部数据库或服务，也不默认上传真实历史；先比较可用方案和数据范围。索引若增加，需验证增量更新、删除同步、版本失效、重建及异常恢复。

候选数量上限、索引参数和排序配置应记录为实验条件；明确的用户项目/来源筛选仍生效，不能用主会话默认目录擅自排除其他项目。召回覆盖不足时仍报告不完整，不能以高分候选掩盖未检查的范围。

## 第 3 项：任务上下文

### 当前依据与目标

当前主会话拥有原生会话历史、固定工作说明及主动工具检索结果；worker 请求携带目标、约束、验收条件、产物要求和有限的续接来源摘要。原 worker 继续使用自己的原生历史。第 3 项拟将相关资料的筛选与传递标准化，以程序为主、简短 prompt 为辅，不替换会话历史与原生压缩。

此阶段以 B2 的检索能力为固定依赖。需要修改检索算法的发现先记为后续事项，不能与上下文实验混在一起调整；若必须修复检索缺陷，应中止当前比较、重新验证依赖并重建对照后再继续。

### 拟实现方式

Host 共用方法以当前请求、明确选中的任务、原会话身份和当前版本为输入，按预算返回目标、适用约束、步骤及未通过验收项、最近结果、阻塞情况、相关记忆和证据引用。优先使用现有摘要及结构化数据，不默认对每条消息额外调用模型生成摘要。

主会话优先通过 `route`、`get_task` 等现有工具响应取得上下文；普通问答仍按需检索。worker 在 Host 派发前重验身份与版本，再接收相同语义的上下文。DSH 和 Codex 通过各自现有请求入口交付，必要的来源摘录应直接可读，不能假定 Codex 可调用私人助理内部工具来解析证据 ID。

程序按任务、项目、时间和可信状态筛选，已撤回或不适用的记忆不能作为当前要求。历史问题需要的旧记录可以作为明确标注的历史证据保留；候选和冲突不得伪装为确定事实。正文分预算排序，优先保留当前要求、剩余工作和关键限制，次要内容给出可补读的来源。缺失、损坏、截断及版本变化显式返回，不能用旧缓存冒充完整上下文。

prompt 只解释如何使用来源、候选和冲突，不把历史材料提升为系统指令。固定私人助理工作说明保持版本化、去重的现有机制。模型可见内容走支持的原生会话记录路径，使输入可重建。

### 候选实验路线

| 顺序 | 单步方向 | 需要证实的收益 |
| --- | --- | --- |
| 3A | 主会话工具结果统一带上任务状态、剩余步骤和验收情况 | 降低任务状态误判和遗漏，控制额外 token |
| 3B | worker 派发自动附加已选择任务的必要摘要和当前约束 | 新 worker 与续接 worker 均更稳定遵守要求 |
| 3C | 增加 B2 检索到的相关记忆及必要来源摘录 | 跨会话约束遵守率提升，无无关记忆污染 |
| 3D | 调整内容优先级、预算与有界缓存/按需补读 | 在质量不退化的前提下减少延迟或 token |

每次只验证一个接入点或筛选策略；有必要的程序改动和配套说明可组成最小实验，但须记录两者，不能把收益全部归因于程序或 prompt。仅修改提示词也属于候选实验，接受相同标准。

重复控制按逻辑请求及其重试处理，不以“这段内容曾发过”永久跳过。新请求、重启或原生压缩后应按当前可用上下文重新判断；版本变化使旧缓存失效。打开页面、空闲轮询或重复获取主会话不得触发新注入。重点回归重复排队、并发请求、旧响应覆盖新状态及主会话切换。

## 运行约束与文档收尾

实验应使用可恢复的隔离源码和数据库副本，不能在正在被桌面 profile 加载的插件目录试验尚未通过的行为。真实应用阶段才修改被加载的源码；保持唯一主会话、微信连接、既有 worker 续接、权限和未知执行保护。新的持久数据或索引需预先明确迁移、可重建性及回退方法，不以清空记忆库或主会话作为默认处理。

每个正向步骤应用后，将实际行为更新到现有的历史与记忆、任务与执行、设置与运维及验证文档。实验文档仅在本优化任务进行期间记录逐步证据，不冒充当前产品说明。

全部工作完成或明确终止后，把仍需重复运行的评测数据、评分工具、有效基线与基准说明归入测试和验证体系；把最终生效行为写回整体文档。随后删除本方案、两份逐次实验文档及临时基线报告，清理入口链接，不保留独立的历史迭代开发记录。当前这些文档用于执行仍在进行的基线和待开始的优化任务。
